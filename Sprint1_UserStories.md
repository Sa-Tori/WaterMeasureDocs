# User Stories — Sprint 1 (Каркас + игровой экран)

**Спринт:** 14.11 — 22.11.2026 (9 дней)
**Цель:** работающий экран игры: 3 сосуда, тапы, перелив, победа.
**Артефакт:** играбельный прототип на 1–3 уровнях.
**Критерий готовности:** перелив работает, победа срабатывает, попап показывается.

---

## S1-01: Модель данных (Vessel, Level)

Как разработчик, я хочу создать Java-классы `Vessel` (сосуд) и `Level` (уровень), чтобы хранить информацию о ёмкостях, текущей воде и целевых объёмах.

**Критерии приёмки:**
- Пакет `com.watermeasure.game.model`
- `Vessel`: поля `index`, `capacity`, `currentVolume`, `initialVolume`, `isSource`
- `Level`: поля `id`, `List<Vessel> vessels`, `targetVolume`, `List<State> solution` (опционально)
- Валидация: `capacity > 0`, `0 ≤ currentVolume ≤ capacity`
- `isSource = true` — обычный сосуд, но с флагом для исключения из проверки победы
- Геттеры и сеттеры (или финальные поля + конструктор)

---

## S1-02: Правило перелива (TransferWater)

Как игрок, я хочу, чтобы игра правильно считала перелив воды, чтобы математика задачи не ломалась.

**Критерии приёмки:**
- Метод `TransferWater.transfer(Vessel src, Vessel dst)` возвращает `boolean`
- `src == dst` → no-op, `return false`
- `src.currentVolume == 0` → no-op, `return false`
- `dst` полный → no-op, `return false`
- Иначе: `amount = min(src.currentVolume, dst.capacity − dst.currentVolume)`, перенос
- Никакой специальной обработки для `isSource` нет — он переливается как обычный сосуд

---

## S1-03: Проверка победы (CheckWin)

Как игрок, я хочу, чтобы игра засчитывала победу, когда я получаю нужный объём.

**Критерии приёмки:**
- Метод `CheckWin.check(Level level)` возвращает `boolean`
- `true`, если в любом сосуде с `isSource == false` `currentVolume == targetVolume`
- `isSource == true` исключается из проверки

---

## S1-04: Заготовка GameView (Canvas)

Как разработчик, я хочу создать кастомный `View` для отрисовки игрового поля, чтобы затем рисовать сосуды и воду.

**Критерии приёмки:**
- Класс `GameView` наследует `View`, переопределяет `onDraw(Canvas canvas)`
- Пустой фон (или лёгкая заливка)
- Пока без сосудов — только каркас для дальнейшей отрисовки

---

## S1-05: Отрисовка 3 сосудов + вода

Как игрок, я хочу видеть сосуды с водой на экране, чтобы понимать текущее состояние уровня.

**Критерии приёмки:**
- Рисуются 3 сосуда в виде прямоугольников
- Внутри каждого — голубой прямоугольник, высота пропорциональна `currentVolume / capacity`
- Никаких спрайтов из Unity — только `Canvas` и геометрические фигуры

---

## S1-06: Обработка тапов (выбор сосуда)

Как игрок, я хочу выбирать сосуд тапом, чтобы затем перелить в него воду.

**Критерии приёмки:**
- Обработка `onTouchEvent` в `GameView`
- Тап по непустому сосуду → сосуд становится выбранным (подсветка)
- Тап по пустому сосуду → выделение не срабатывает
- Повторный тап по выбранному сосуду → выделение снимается

---

## S1-07: Перелив при тапе по другому сосуду

Как игрок, я хочу переливать воду тапом по сосуду-приёмнику.

**Критерии приёмки:**
- При наличии выбранного сосуда тап по другому сосуду вызывает `TransferWater.transfer`
- После перелива — обновление отрисовки (`invalidate()`)
- Выделение снимается после перелива

---

## S1-08: Попап «Уровень пройден»

Как игрок, я хочу видеть сообщение о победе, когда достигаю цели.

**Критерии приёмки:**
- При `CheckWin.check(level) == true` показывается попап (диалог или оверлей)
- Текст: «Уровень N пройден!»
- Кнопка «Продолжить» → закрытие попапа (для прототипа)

---

## S1-09: Номер уровня в UI

Как игрок, я хочу видеть, на каком уровне я нахожусь.

**Критерии приёмки:**
- В верхней части `GameView` (или в `GameActivity`) отображается текст «Уровень: N»
- Номер соответствует текущему уровню

---

## S1-10: Ревью и закрытие спринта

Как тимлид, я хочу проверить прототип, чтобы убедиться, что он играбелен.

**Критерии приёмки:**
- Прототип запускается на эмуляторе или устройстве
- Можно пройти 1–3 уровня (перелив работает, победа срабатывает)
- Нет критичных багов (падений, зависаний)
- Код в репозитории, структура пакетов соблюдена
