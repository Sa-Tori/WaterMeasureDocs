## S1-01: Модель данных
**Как разработчик,** я хочу создать Java-классы `Vessel` (сосуд) и `Level` (уровень), чтобы хранить информацию о ёмкостях, текущей воде и целевых объёмах.

**Критерии приёмки:**
- Пакет `com.watermeasure.game.model`
- `Vessel`: поля `index`, `capacity`, `currentVolume`, `isSource`
- `Level`: поля `id`, `List<Vessel> vessels`, `targetVolume`, `List<int[]> solutionSteps` (опционально)
- Валидация: `capacity > 0`, `0 ≤ currentVolume ≤ capacity`
- `isSource = true` — обычный сосуд, но с флагом для исключения из проверки победы
- Есть геттеры и сеттеры

## S1-02: Правила перелива
**Как игрок,** я хочу, чтобы игра правильно считала перелив воды, чтобы математика задачи не ломалась.

**Критерии приёмки:**
- Метод `TransferWater.transfer(Vessel src, Vessel dst)` возвращает `boolean`
- `src == dst` → no-op, return `false`
- `src.currentVolume == 0` → no-op, return `false`
- `dst` полный → no-op, return `false`
- Иначе: `amount = min(src.currentVolume, dst.capacity − dst.currentVolume)`, перенос
- **Никакой специальной обработки для `isSource` нет** — он переливается как обычный сосуд

## S1-03: Проверка победы
**Как игрок,** я хочу, чтобы игра засчитывала победу, когда я получаю нужный объём.

**Критерии приёмки:**
- Метод `CheckWin.check(Level level)` возвращает `boolean`
- `true`, если **в любом сосуде с `isSource == false`** `currentVolume == targetVolume`
- `isSource == true` **исключается** из проверки

## S1-04: Unit-тесты (JUnit 5)
**Как QA,** я хочу покрыть математику тестами, чтобы убедиться, что всё работает без багов.

**Критерии приёмки:**
- 10+ тестов, все зелёные
- Покрыто: перелив меньше/больше, полный/пустой dst, src == dst, `isSource` как обычный сосуд, CheckWin (+/−/исключение `isSource`)

## S1-05: Загрузка уровней (LevelRepository)
**Как разработчик,** я хочу загружать данные уровней из JSON-файла, чтобы не хардкодить их в Java.

**Критерии приёмки:**
- JSON в `app/src/main/res/raw/levels.json`
- Класс читает JSON и возвращает `List<Level>`
- Все 20 уровней парсятся без ошибок
- В JSON есть поля `id`, `vessels` (с `capacity`, `initialVolume`, `isSource`), `targetVolume` и (опционально) `solutionSteps`

## S1-06: Симуляция решений
**Как разработчик,** я хочу прогнать все 20 уровней через BFS-солвер, чтобы убедиться, что они решаемы.

**Критерии приёмки:**
- Тест `LevelSolvabilityTest`: для каждого из 20 уровней BFS находит решение
- BFS работает с 3-мерным состоянием (включая `isSource`)
- Отчёт: 20/20 решаемы
