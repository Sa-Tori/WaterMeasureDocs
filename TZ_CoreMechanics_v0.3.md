## 1. Назначение и область

Документ описывает **правила ядра** игры-головоломки Water Measure: модель данных, правило перелива, условие победы, ограничения, счётчики, жизни, Undo/Restart и контракт подсказок. Задача ТЗ — дать однозначную спецификацию, по которой можно написать код и unit-тесты (S1-01…S1-04) без домыслов.

Всё, что касается отрисовки, экранов, хранения прогресса, звука и монетизации, — **вне области** этого документа.

Игра — моделирование математических задач на переливание воды. Цветов нет, смешивания нет. Есть ёмкости с водой и целевой объём, который нужно получить.

---

## 2. Термины и определения

- **Сосуд (Vessel)** — ёмкость с водой. Характеризуется `capacity` (полный объём), `current` (текущий объём) и `initial` (стартовый объём).
- **Источник (Source)** — сосуд с флагом `isSource = true`. Внешне для игрока — кран/раковина, из которого можно наливать и в который можно выливать. **Технически — обычный сосуд с конечной ёмкостью.** Специальной логики перелива для него нет.
- **Состояние (State)** — массив `current` всех сосудов уровня, включая источник. `State = int[N]`, где N — число сосудов в уровне.
- **Ход (Move)** — одно действие перелива: `Move(source, target, amount)`. `source` и `target` — индексы сосудов. Маркеры `SOURCE` / `SINK` зарезервированы на будущее и в v0.3 не используются.
- **Шаг** — успешный ход (`amount > 0`). Неуспешный (`amount = 0`) шагом не считается.
- **Целевой объём (targetVolume)** — объём, который должен оказаться в **любом сосуде, кроме источника**.
- **Решение (solution)** — упорядоченный список состояний `List<State>` от стартового до победного. Используется для подсказок.
- **Ограничение (limit)** — необязательное условие уровня: `stepLimit` (макс. шагов) и/или `timeLimit` (макс. секунд).
- **Жизнь (Life)** — мета-ресурс игрока. Максимум 5. Восстанавливается 1 за 10 минут. Списывается при поражении и ручном рестарте **активного** (непройденного) уровня.
- **Активный уровень** — уровень, который ещё не пройден и на котором сейчас играет игрок. Только на нём списываются жизни.
- **Пройденный уровень** — уровень, который уже завершён. Его можно перепройти без списания жизни.

## 3. Модель данных

### 3.1 Vessel

| Поле | Тип | Ограничение | Описание |
|---|---|---|---|
| `capacity` | `Int` | `> 0` | Полный объём сосуда |
| `current` | `Int` | `0 ≤ current ≤ capacity` | Текущий объём (изменяется в игре) |
| `initial` | `Int` | `0 ≤ initial ≤ capacity` | Стартовый объём (для Restart) |
| `isSource` | `Boolean` | — | `true` для источника (кран) |

Инвариант: `current ∈ [0, capacity]` всегда.

### 3.2 Level

| Поле | Тип | Ограничение | Описание |
|---|---|---|---|
| `id` | `Int` | `> 0` | Номер уровня |
| `vessels` | `List<Vessel>` | `size ∈ {2, 3}` в v0.3; расширяемо | Сосуды уровня (порядок важен для UI) |
| `targetVolume` | `Int` | `> 0`, `≤ max(capacity)` | Целевой объём |
| `stepLimit` | `Int?` | `null` или `> 0` | Макс. шагов; `null` — без лимита |
| `timeLimit` | `Int?` | `null` или `> 0` (сек) | Макс. времени; `null` — без лимита |
| `solution` | `List<State>?` | `null` или `size ≥ 2` | Путь решения (для подсказок); `null` — подсказки недоступны |

**Примечание:** в текущих 20 уровнях всегда 3 сосуда (включая источник). Расширение до 4+ потребует пересмотра сложности и баланса (открытый вопрос GDD).

Валидация уровня (проверяется в S1-06):
- ровно один `isSource = true` **или** ни одного;
- стартовое состояние не содержит `targetVolume` ни в одном сосуде (иначе мгновенная победа);
- `solution[0]` совпадает со стартовым состоянием;
- последний элемент `solution` содержит `targetVolume` в каком-то сосуде;
- каждый переход `solution[i] → solution[i+1]` — валидный одиночный перелив (см. §4);
- сумма `current` по всем сосудам сохраняется на каждом переходе.

### 3.3 State

```
State = int[] длиной N (N = vessels.size())
State[i] = vessels[i].current
```

Сравнение состояний — поэлементное (для поиска в `solution`).

### 3.4 Move

```
Move {
    source: Int   // индекс сосуда
    target: Int   // индекс сосуда
    amount: Int   // > 0
}
```

В v0.3 `SOURCE` / `SINK` не используются. Источник — обычный сосуд.

## 4. Правила перелива

### 4.1 Общая формула

Для пары сосудов `(src, dst)`, `src ≠ dst`:

```
amount = min(src.current, dst.capacity − dst.current)
```

Если `amount = 0` → ход **невалиден**, ничего не происходит, шаг не засчитывается.

Если `amount > 0`:
```
src.current -= amount
dst.current += amount
steps += 1
history.push(state_before_move)
```

**Специальной обработки для `isSource` нет.** Источник переливается как обычный сосуд.

### 4.2 Перелив сосуд → сосуд

Стандартный случай. Работает по формуле §4.1.

### 4.3 Перелив источник → сосуд

Источник — обычный сосуд (`isSource = true`), правило то же. Отличие только в UI: рисуется как кран/раковина.

### 4.4 Перелив сосуд → источник

То же правило. Игрок «выливает» воду в кран.

### 4.5 Запрещённые и невалидные ходы

| Ситуация | Поведение |
|---|---|
| `src == dst` | Невалидно, ничего не происходит, выделение снимается |
| `src.current == 0` | `amount = 0` → невалидно |
| `dst.current == dst.capacity` | `amount = 0` → невалидно |
| `amount = 0` по любой причине | Невалидно, шаг не засчитывается, состояние не меняется |

**Важно:** невалидный ход не считается ошибкой — это просто «ничего не произошло». UI может дать визуальный отклик (например, короткую анимацию «нельзя»), но это вне ядра.

### 4.6 Правила выбора сосудов в UI (влияют на ядро)

Эти правила описывают, какие тапы приводят к вызову `TransferWater`. Реализация — в View/ViewModel, но контракт фиксируется здесь.

1. **Нет выбранного сосуда, тап по непустому сосуду** → сосуд становится источником, подсвечивается.
2. **Нет выбранного сосуда, тап по пустому сосуду** → выделение **не срабатывает** (пустой сосуд нельзя выбрать как источник).
3. **Есть выбранный сосуд, тап по тому же сосуду** → выделение снимается.
4. **Есть выбранный сосуд, тап по другому сосуду** → попытка перелива по §4.1.
5. **Есть выбранный сосуд, тап по полному сосуду** → перелив невозможен (`amount = 0`). Выделение с первого сосуда снимается, а полный сосуд становится новым выбранным источником (если в нём есть вода).
6. **Есть выбранный сосуд, тап по пустому сосуду** → это валидный приёмник, перелив происходит по §4.1.

## 5. Условие победы

Победа наступает, если **хотя бы один** сосуд, **кроме источника**, имеет `current == targetVolume`.

Формально:
```
win(state) = ∃ i ∈ vessels, !vessels[i].isSource : state[i] == targetVolume
```

Источник **не может быть целевым сосудом**.

Проверка выполняется **после каждого успешного хода**. Если стартовое состояние уже содержит `targetVolume` — это ошибка данных уровня (валидация §3.2), а не победа.

Победа **не проверяется** после Undo/Restart (они откатывают состояние, победы не создают).

## 6. Ограничения, поражение и жизни

### 6.1 stepLimit

Если `stepLimit != null` и после хода `steps > stepLimit` → **поражение**.

Проверка: после инкремента `steps`. То есть при `stepLimit = 10` ход, делающий `steps = 11`, — уже поражение.

### 6.2 timeLimit

Если `timeLimit != null` и `elapsed > timeLimit` (в секундах) → **поражение**.

Проверка: в игровом цикле (тик), а не только после хода. При достижении лимита — немедленное поражение.

Пауза (меню, настройки) **останавливает** `elapsed`. Рестарт обнуляет `elapsed`.

### 6.3 Комбинации

| stepLimit | timeLimit | Поведение |
|---|---|---|
| `null` | `null` | Свободное решение, только победа |
| `> 0` | `null` | Лимит шагов |
| `null` | `> 0` | Лимит времени |
| `> 0` | `> 0` | Оба лимита (поражение по любому) |

**В 20 стартовых уровнях (v0.3) оба поля `null`.** Распределение лимитов по уровням — открытый вопрос для GDD.

### 6.4 Отсутствие поражения

Если оба лимита `null` — поражения нет. Тупик **не является поражением**: игрок всегда может нажать Restart.

### 6.5 Жизни (мета-правила, влияющие на ядро)

- Максимум **5 жизней**.
- Восстановление: **1 жизнь за 10 минут**.
- Жизнь списывается:
  - при **поражении** на **активном** уровне (исчерпан `stepLimit` или `timeLimit`);
  - при **ручном рестарте активного** (непройденного) уровня.
- Жизнь **не списывается**:
  - при **выходе из игры** (состояние уровня сохраняется);
  - при **рестарте пройденного** уровня (перепрохождение);
  - при **Undo**;
  - при **прохождении** уровня.
- При **0 жизнях** игрок не может начать новый уровень или продолжить текущий до восстановления следующей жизни. UI показывает таймер до восстановления.
- В будущем (не в первом релизе) возможна монетизация: покупка жизней за донат-валюту или (реже) за просмотр рекламы. **В v0.3 не реализуется**, только заложено место в UI.

## 7. Счётчики: шаги и время

### 7.1 Шаги

- Инкремент: `steps += 1` при `amount > 0`.
- Декремент: `steps -= 1` при Undo.
- Сброс: `steps = 0` при Restart / загрузке уровня.

### 7.2 Время

- `elapsed` — секунды с момента старта уровня (тип `Long`).
- Пауза: `elapsed` **не** растёт, пока уровень на паузе.
- Сброс: `elapsed = 0` при Restart.
- Таймер в ядре — это **счётчик**, а не UI.

## 8. История ходов, Undo, Restart

### 8.1 История

Движок хранит `history: List<State>` — состояния **до** каждого успешного хода. Рекомендуемая реализация: `history` хранит **все** состояния, включая текущее. Тогда:
- Undo = удалить последнее, текущее = `history.last()`.
- Restart = `history = [initialState]`.

### 8.2 Undo

```
undo():
    if history.size() <= 1: return
    history.removeLast()
    steps = max(0, steps − 1)
    // timeLimit — не откатывается (время идёт)
```

**В v0.3 (ядро) Undo — отдельная механика, реализуется в ViewModel.**
**Стоимость: 10 монет** (первичная цифра, может измениться после тестирования прототипа). Списывание монет — вне ядра.

**Обоснование:** «перелить назад» не всегда возможно. Пример: A=2/3, B=1/5 → A→B даёт A=0, B=3; обратно B→A даёт A=3, B=0 ≠ исходное. Undo не избыточен.

### 8.3 Restart

```
restart():
    for v in vessels: v.current = v.initial
    history = [initialState]
    steps = 0
    elapsed = 0
    // списание жизни — на уровне UI/мета, не в ядре
```

Restart **не** списывает шаги (они обнуляются) и **не** влияет на `stepLimit`/`timeLimit`.

Списывание жизни при ручном рестарте — только если уровень **активный** (не пройден). Рестарт пройденного — бесплатно.

## 9. Контракт подсказок (ядро)

### 9.1 Вход / выход

```
getHint(level: Level, currentState: State): Move?
```

Возвращает следующий ход или `null`, если подсказка невозможна.

### 9.2 Алгоритм

1. Если `level.solution == null` → `null`.
2. Найти индекс `i`, где `solution[i] == currentState`.
3. Если `i == -1` или `i == solution.size() − 1` → `null`.
4. `nextState = solution[i + 1]`.
5. Определить `Move` из `currentState → nextState`:
   - найти `src`, где `currentState[src] > nextState[src]`;
   - найти `dst`, где `currentState[dst] < nextState[dst]`;
   - `amount = currentState[src] − nextState[src]`;
   - вернуть `Move(src, dst, amount)`.

### 9.3 Ограничения контракта

- Контракт **не** описывает, как ход отрисовывается — это UI.
- Контракт **не** описывает, как вызывается — это UI/геймдизайн.
- Стоимость подсказки — **20 монет** (первичная цифра, может измениться).
- Если `getHint` вернул `null` — UI показывает «вернись к решению» / Restart.

## 11. Критерии приёмки (для S1-04)

### 11.1 Правило перелива

1. Перелив 5 из 7 в бутылку с `capacity 10, current 3` → в target 5, в source −5.
2. Перелив из пустого сосуда → `amount = 0`, состояние не меняется.
3. Перелив в полный сосуд → `amount = 0`, состояние не меняется.
4. Перелив в себя → запрещён, состояние не меняется.
5. Перелив из сосуда в источник → работает как в обычный сосуд.
6. Перелив из источника в сосуд → работает как из обычного сосуда.
7. Сумма `current` сохраняется после каждого перелива.

### 11.2 Победа

8. Сосуд с `current == targetVolume` → победа.
9. Ни один сосуд не достиг `targetVolume` → победы нет.
10. Источник с `current == targetVolume` → **не** победа.
11. Стартовое состояние содержит `targetVolume` → ошибка валидации уровня (не победа).

### 11.3 Ограничения и жизни

12. `stepLimit = 3`, после 4-го шага → поражение.
13. `stepLimit = 3`, после 3-го шага и достижения цели → победа (не поражение).
14. `timeLimit = 60`, на 61-й секунде → поражение.
15. `stepLimit = null`, `timeLimit = null` → поражения нет.
16. `stepLimit` и `timeLimit` оба заданы → поражение по любому.
17. При поражении на **активном** уровне списывается 1 жизнь (мета).
18. При ручном рестарте **активного** уровня списывается 1 жизнь (мета).
19. При ручном рестарте **пройденного** уровня жизнь **не** списывается.
20. При выходе из игры жизнь не списывается.

### 11.4 Шаги и Undo

21. Успешный перелив → `steps += 1`.
22. Неуспешный перелив → `steps` не меняется.
23. Undo → состояние и `steps` откатываются.
24. Restart → состояние, `steps`, `elapsed` обнуляются.
25. Undo с пустой историей → ничего не происходит.

### 11.5 Подсказки

26. `getHint` на стартовом состоянии → корректный `Move` из `solution[0] → solution[1]`.
27. `getHint` на состоянии вне `solution` → `null`.
28. `getHint` на победном состоянии → `null`.
29. `getHint` при `solution = null` → `null`.

### 11.6 Уровни

30. Все 20 уровней проходят валидацию §3.2.
31. Все 20 уровней решаемы (Solver находит решение).
32. Все 20 `solution` (если заданы) валидны.
