# TechSpec v0.2 — Water Measure

**Версия:** 0.2
**Статус:** Final for Sprint 0
**Стек:** Android Studio, Java, MVVM, Room, DataStore, JSON.

---

## 1. Архитектура приложения (MVVM)

Для того чтобы код не превратился в «кашу» и Gemini не путался, используем паттерн **MVVM**. Проект разделён на пакеты:

1. **`model`** — чистая математика и правила игры. Здесь нет UI. Классы `Vessel`, `Level`, `GameEngine`, `TransferWater`, `CheckWin`, `HintProvider`.
2. **`view`** — экраны (Activities) и кастомные отрисовщики (Custom Views). Только то, что видит игрок.
3. **`viewmodel`** — связующее звено. Хранит текущее состояние игры (выбранные бутылки, шаги, время, жизни) и передаёт данные из Model в View.
4. **`data`** — работа с Room, DataStore, загрузка JSON.

---

## 2. Экраны и навигация (View)

В приложении **3 основных экрана**:

1. **`MainMenuActivity`** — главное меню. Кнопки: «Играть», «Настройки», «Выход».
2. **`LevelSelectActivity`** — выбор уровня. Сетка из 20 кнопок. Заблокированные уровни неактивны (серые).
3. **`GameActivity`** — игровой экран.

**Особенности игрового экрана (`GameActivity`):**
- **Верхняя панель:** номер уровня, монеты, таймер (если есть), **жизни (5 сердечек/иконок)**.
- **Центр:** кастомный `GameView` (наследник `View`). Рисуем бутылки кодом на `Canvas`. PNG-спрайты из Unity не используем. Вода заливается цветом, выбранная бутылка выделяется рамкой.
- **Нижняя панель:** кнопки «Подсказка», «Сброс», «Меню», «Отмена хода» (если доступна).

**Ориентация:** портретная.

## 3. Сохранение данных (Room + DataStore)

Сохраняем всё, чтобы игрок не терял прогресс.

### 3.1 DataStore (настройки и мета)

Хранит простые настройки:
- `isSoundOn: Boolean`
- `isMusicOn: Boolean`
- `coins: Int`
- `unlockedLevels: Int`
- `lives: Int` — текущее количество жизней (0…5)
- `nextLifeTime: Long` — timestamp (мс) до восстановления следующей жизни
- `language: String` — `"ru"` или `"en"`
- `selectedLevel: Int` — последний выбранный уровень

### 3.2 Room Database (игровой прогресс и состояние)

Таблица `GameState`:
- `levelId` (Int) — номер уровня.
- `isCompleted` (Boolean) — пройден ли уровень.
- `bestSteps` (Int) — лучшее количество шагов.
- `currentStateJson` (String) — **ВАЖНО:** текущее состояние воды в бутылках, если игрок выходит из игры на середине уровня. При загрузке игра восстанавливает бутылки ровно там, где игрок остановился.
- `currentSteps` (Int) — текущее количество шагов на уровне.
- `currentElapsed` (Long) — текущее время на уровне (сек).
- `updatedAt` (Long) — timestamp последнего сохранения.

**Правило:** при выходе из игры состояние уровня сохраняется, жизни **не** списываются.

## 4. Контент и уровни (JSON)

Уровни **не хардкодятся** в Java. Они хранятся в `app/src/main/res/raw/levels.json`.

Формат файла:
```json
{
  "levels": [
    {
      "id": 1,
      "vessels": [
        {"capacity": 3, "initial": 0, "isSource": false},
        {"capacity": 5, "initial": 0, "isSource": false},
        {"capacity": 8, "initial": 8, "isSource": false}
      ],
      "targetVolume": 4,
      "stepLimit": null,
      "timeLimit": null,
      "solution": [
        [0, 0, 8],
        [0, 5, 3]
      ]
    }
  ]
}
```

При запуске класс `LevelRepository` читает `R.raw.levels` через `context.getResources().openRawResource(...)`, парсит через Gson и отдаёт `List<Level>`.

## 5. Логика подсказок (Hint System)

Подсказки работают на основе массива `solution` из JSON.

1. Игрок нажимает кнопку «Подсказка».
2. `GameViewModel` берёт текущее состояние бутылок (например, `[0, 5, 3]`).
3. Ищет это состояние в массиве `solution` для текущего уровня.
4. Если находит — берёт **следующее** состояние (например, `[3, 2, 3]`) и вычисляет, из какой бутылки в какую нужно перелить.
5. Возвращает UI команду: «Подсвети бутылку 1 и бутылку 3».
6. Если состояние не найдено — UI показывает «вернись к решению» / предлагает Restart.

Стоимость подсказки — 20 монет (мета, списывается в ViewModel).

## 6. Жизни (LifeManager)

- Максимум **5 жизней**.
- Восстановление: **1 жизнь за 10 минут**.
- Хранение: `DataStore` (`lives`, `nextLifeTime`).
- Логика:
  - При поражении (исчерпан `stepLimit` / `timeLimit`) — `lives -= 1`.
  - При ручном рестарте уровня — `lives -= 1`.
  - При выходе из игры — жизни **не** списываются.
  - Если `lives < 5` и `now >= nextLifeTime` — восстановить 1 жизнь, обновить `nextLifeTime`.
  - При `lives == 0` — блокировать старт/продолжение уровня до восстановления. UI показывает таймер.
- Восстановление работает и при закрытом приложении (по timestamp).

## 7. Локализация

- Поддерживаемые языки: **русский (ru)** и **английский (en)**.
- Все тексты — в `strings.xml`:
  - `app/src/main/res/values/strings.xml` — английский (default).
  - `app/src/main/res/values-ru/strings.xml` — русский.
- При первом запуске язык определяется по системной локали (если `ru` — русский, иначе английский).
- Игрок может сменить язык в настройках. Выбор сохраняется в `DataStore` (`language`).
- При смене языка Activity пересоздаётся с новой локалью.

## 9. Инструкция для агента Gemini

1. **Не смешивай логику и UI.** `GameEngine.java` ничего не знает о кнопках и `Canvas`. Он принимает состояние и возвращает новое состояние.
2. **Используй Java.** Никакого Kotlin.
3. **Интерфейс рисуй кодом.** В `GameView.java` переопредели `onDraw(Canvas canvas)`. Рисуй прямоугольники (`canvas.drawRect`). Высоту воды считай в процентах от `capacity`.
4. **Соблюдай иерархию пакетов** (см. §1).
5. **Источник — обычный сосуд.** Не пиши отдельную логику перелива для `isSource`. Флаг нужен только для `CheckWin` и UI.
6. **Жизни, Undo, локализация** — в Sprint 2+. В Sprint 1 только ядро.
7. **JSON — в `res/raw/levels.json`.** Читай через `R.raw.levels`.
