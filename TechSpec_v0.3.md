# TechSpec v0.3 — Water Measure

**Версия:** 0.3
**Статус:** Final for Sprint 0
**Стек:** Android Studio, Java, MVVM, Room, DataStore, JSON.

---

## 1. Архитектура приложения (MVVM)

Проект разделён на пакеты:

1. **`model`** — чистая математика. Классы `Vessel`, `Level`, `GameEngine`, `TransferWater`, `CheckWin`, `HintProvider`.
2. **`view`** — экраны (Activities) и кастомные отрисовщики (Custom Views).
3. **`viewmodel`** — связующее звено. Хранит состояние игры (выбранные бутылки, шаги, время, жизни) и передаёт данные из Model в View.
4. **`data`** — Room, DataStore, загрузка JSON.

---

## 2. Экраны и навигация (View)

**3 основных экрана:**

1. **`MainMenuActivity`** — главное меню. Кнопки: «Играть», «Настройки», «Выход».
2. **`LevelSelectActivity`** — выбор уровня. Сетка из 20 кнопок. Заблокированные уровни неактивны (серые). Пройденные — отмечены (галочка/звёзды).
3. **`GameActivity`** — игровой экран.

**Особенности игрового экрана (`GameActivity`):**
- **Верхняя панель:** номер уровня, монеты, таймер (если есть), **жизни (5 сердечек/иконок)**.
- **Центр:** кастомный `GameView` (наследник `View`). Рисуем бутылки кодом на `Canvas`. PNG-спрайты из Unity не используем. Вода заливается цветом, выбранная бутылка выделяется рамкой.
- **Нижняя панель:** кнопки «Подсказка», «Сброс», «Меню», «Отмена хода» (если доступна).

**Ориентация:** портретная.

## 3. Сохранение данных (Room + DataStore)

### 3.1 DataStore (настройки и мета)

- `isSoundOn: Boolean`
- `isMusicOn: Boolean`
- `coins: Int`
- `unlockedLevels: Int`
- `lives: Int` — текущее количество жизней (0…5)
- `nextLifeTime: Long` — timestamp (мс) до восстановления следующей жизни
- `lastLifeSpendTime: Long` — timestamp (мс) последней траты жизни (для расчёта восстановления)
- `language: String` — `"ru"` или `"en"`
- `selectedLevel: Int` — последний выбранный уровень

### 3.2 Room Database (игровой прогресс и состояние)

Таблица `GameState`:
- `levelId` (Int) — номер уровня.
- `isCompleted` (Boolean) — пройден ли уровень.
- `bestSteps` (Int) — лучшее количество шагов.
- `currentStateJson` (String) — текущее состояние воды в бутылках.
- `currentSteps` (Int) — текущее количество шагов на уровне.
- `currentElapsed` (Long) — текущее время на уровне (сек).
- `updatedAt` (Long) — timestamp последнего сохранения.

**Правило:** при выходе из игры состояние уровня сохраняется, жизни **не** списываются.

## 4. Контент и уровни (JSON)

Уровни хранятся в `app/src/main/res/raw/levels.json`.

```json
{
  "levels": [
    {
      "id": 1,
      "vessels": [
        {"capacity": 3, "initial": 0, "isSource": false},
        {"capacity": 5, "initial": 0, "isSource": false},
        {"capacity": 8, "initial": 8, "isSource": false}
      ],
      "targetVolume": 4,
      "stepLimit": null,
      "timeLimit": null,
      "solution": [
        [0, 0, 8],
        [0, 5, 3]
      ]
    }
  ]
}
```

`LevelRepository` читает `R.raw.levels` через `context.getResources().openRawResource(...)`, парсит через Gson, возвращает `List<Level>`.

## 5. Логика подсказок (Hint System)

1. Игрок нажимает «Подсказка».
2. `GameViewModel` берёт текущее состояние (`[0, 5, 3]`).
3. Ищет в `solution` текущего уровня.
4. Если находит — берёт **следующее** состояние (`[3, 2, 3]`) и вычисляет, откуда куда перелить.
5. Возвращает UI: «Подсвети бутылку 1 и бутылку 3».
6. Если не найдено — UI показывает «вернись к решению» / Restart.

**Стоимость: 20 монет** (первичная цифра, может измениться после тестирования).

## 6. Жизни (LifeManager)

- Максимум **5 жизней**.
- Восстановление: **1 жизнь за 10 минут**.
- Хранение: `DataStore` (`lives`, `nextLifeTime`, `lastLifeSpendTime`).

### 6.1 Логика списывания

- При **поражении** на **активном** (непройденном) уровне — `lives -= 1`, `lastLifeSpendTime = now`.
- При **ручном рестарте активного** уровня — `lives -= 1`, `lastLifeSpendTime = now`.
- При **рестарте пройденного** уровня — **без списания**.
- При **выходе из игры** — **без списания**.

### 6.2 Восстановление

- Работает и при **закрытом** приложении, и при **открытом**.
- Основа — **реальное время телефона** (или системное время), не аптайм.
- Формула:
  ```
  elapsedSinceSpend = now - lastLifeSpendTime
  recovered = min(5 - lives, elapsedSinceSpend / (10 * 60 * 1000))
  lives += recovered
  if recovered > 0: lastLifeSpendTime = now - (elapsedSinceSpend % (10 * 60 * 1000))
  ```
- При `lives == 5` — восстановление останавливается.

### 6.3 При 0 жизнях

- Блокировать старт нового уровня и продолжение текущего.
- UI показывает таймер до восстановления.
- **В будущем (не в первом релизе):** возможность купить жизнь за донат-валюту или (реже) за рекламу. **В v0.3 не реализуется**, только заложено место в UI.

## 7. Локализация

- Поддерживаемые языки: **русский (ru)** и **английский (en)**.
- Все тексты — в `strings.xml`:
  - `app/src/main/res/values/strings.xml` — английский (default).
  - `app/src/main/res/values-ru/strings.xml` — русский.
- При первом запуске язык определяется по системной локали.
- Игрок может сменить язык в настройках. Выбор сохраняется в `DataStore` (`language`).
- При смене языка Activity пересоздаётся с новой локалью.

## 9. Инструкция для агента Gemini

1. **Не смешивай логику и UI.** `GameEngine.java` ничего не знает о кнопках и `Canvas`.
2. **Используй Java.** Никакого Kotlin.
3. **Интерфейс рисуй кодом.** В `GameView.java` переопредели `onDraw(Canvas canvas)`. Рисуй прямоугольники (`canvas.drawRect`). Высоту воды считай в процентах от `capacity`.
4. **Соблюдай иерархию пакетов** (см. §1).
5. **Источник — обычный сосуд.** Не пиши отдельную логику перелива для `isSource`. Флаг нужен только для `CheckWin` и UI.
6. **Жизни, Undo, локализация** — в Sprint 2+.
7. **JSON — в `res/raw/levels.json`.** Читай через `R.raw.levels`.
