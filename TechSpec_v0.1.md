# TechSpec v0.1 — Water Measure

**Версия:** 0.1 (черновик)
**Статус:** Готов к использованию для генерации кода
**Стек:** Android Studio, Java, MVVM, Room, DataStore, JSON.

---

## 1. Архитектура приложения (MVVM)

Для того чтобы код не превратился в «кашу» и Gemini не путался, мы используем паттерн **MVVM (Model-View-ViewModel)**. Проект будет разделен на четкие пакеты (папки):

1. **`model` (Модель):** Чистая математика и правила игры. Здесь нет UI. Здесь живут классы `Vessel`, `Level`, `GameEngine`.
2. **`view` (Представление):** Экраны (Activities) и кастомные отрисовщики (Custom Views). Здесь только то, что видит игрок.
3. **`viewmodel` (Вью-модель):** Связующее звено. Хранит текущее состояние игры (какие бутылки выбраны, сколько шагов сделано) и передает данные из Модели в Представление.
4. **`data` (Данные):** Работа с базой данных (Room) и настройками (DataStore), а также загрузка JSON-файлов.

---

## 2. Экраны и Навигация (View)

В приложении будет **3 основных экрана**:

1. **`MainMenuActivity`** — Главное меню. Стандартные кнопки Android: «Играть», «Настройки», «Выход».
2. **`LevelSelectActivity`** — Выбор уровня. Сетка из 20 кнопок. Заблокированные уровни неактивны (серые).
3. **`GameActivity`** — Игровой экран.

**Особенности игрового экрана (`GameActivity`):**
*   **Верхняя панель:** Номер уровня, монеты, таймер (если есть).
*   **Центр:** Кастомный `GameView` (наследник `View`). Рисуем бутылки кодом на `Canvas`. Нам не нужны PNG-спрайты из Unity. Заливаем воду цветом, выделяем выбранную бутылку рамкой.
*   **Нижняя панель:** Кнопки «Подсказка», «Сброс», «Меню».

---

## 3. Сохранение данных (Room + DataStore)

Мы сохраняем **всё**, чтобы игрок не терял прогресс.

### 3.1. DataStore (Настройки)
Хранит простые настройки:
*   Включен ли звук (`isSoundOn: Boolean`)
*   Включена ли музыка (`isMusicOn: Boolean`)
*   Всего монет (`coins: Int`)
*   Сколько уровней разблокировано (`unlockedLevels: Int`)

### 3.2. Room Database (Игровой прогресс и состояние)
Таблица `GameState`:
*   `levelId` (Int) — номер уровня.
*   `isCompleted` (Boolean) — пройден ли уровень.
*   `bestSteps` (Int) — лучшее количество шагов.
*   `currentStateJson` (String) — **ВАЖНО!** Сюда мы сохраняем текущее состояние воды в бутылках, если игрок выходит из игры на середине уровня. При загрузке игра восстановит бутылки ровно там, где игрок остановился.

## 4. Контент и Уровни (JSON)

Уровни **не хардкодятся** в коде Java. Они хранятся в папке `assets` в файле **`levels.json`**. 
Формат файла:
```json
[
  {
    "id": 1,
    "vessels": [
      {"capacity": 3, "initial": 0, "isSource": false},
      {"capacity": 5, "initial": 0, "isSource": false},
      {"capacity": 8, "initial": 8, "isSource": false}
    ],
    "targetVolume": 4,
    "solution": [
      [0, 0, 8],
      [0, 5, 3]
    ]
  }
]
```
При запуске игры класс `LevelRepository` читает этот файл и отдает данные в игру.

## 5. Логика подсказок (Hint System)

Подсказки работают на основе массива `solution` из JSON-файла.
1. Игрок нажимает кнопку «Подсказка».
2. `GameViewModel` берет текущее состояние бутылок (например, `[0, 5, 3]`).
3. Ищет это состояние в массиве `solution` для текущего уровня.
4. Если находит, берет **следующее** состояние (например, `[3, 2, 3]`) и вычисляет, из какой бутылки в какую нужно перелить.
5. Возвращает UI команду: «Подсвети бутылку 1 и бутылку 3».

## 6. Сторонние библиотеки

*   `Room` — для базы данных.
*   `DataStore` — для настроек.
*   `Gson` или `Moshi` — для парсинга JSON-файлов.
*   `ViewModel` и `LiveData` (или `StateFlow`) — для связи UI и данных.

---

## 7. Инструкция для агента Gemini (Как это делать)

1.  **Не смешивай логику и UI.** `GameEngine.java` ничего не знает о кнопках и `Canvas`. Он просто принимает координаты бутылок и возвращает новое состояние.
2.  **Используй Java.** Никакого Kotlin. 
3.  **Интерфейс рисуй кодом.** В `GameView.java` переопредели метод `onDraw(Canvas canvas)`. Рисуй прямоугольники (`canvas.drawRect`). Высоту воды считай в процентах от `capacity`.
4.  **Соблюдай иерархию пакетов.** (см. пункт 1).
